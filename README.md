# 养老机构分药盒管理系统

按**医嘱版本**与**餐次**准备住户分药盒，药师核对药名 / 规格 / 数量 / 禁忌后双签签发，
护理员按床位交接，床旁记录签收 / 拒服 / 暂缓。全程写入 SQLite 哈希签发链，封盒照片本地留存。

零第三方依赖：仅使用 Python 3.10+ 标准库（`http.server` / `sqlite3` / `zlib`）。

## 单条本地命令启动（自动生成停药样例）

```bash
python3 -m medbox
# 可选：--db data/medbox.db --photos data/photos --host 127.0.0.1 --port 8000
```

启动后：

- 总览：<http://127.0.0.1:8000/>
- 配药 / 装盒核对 / 双人复核端：<http://127.0.0.1:8000/static/pharmacy.html>
- 床旁执行端（大号确认键 + 剩余未执行项）：<http://127.0.0.1:8000/static/bedside.html>

进程启动时自动建库、播种演示数据（含临时停药样例），进程内守护线程每分钟做一次
服药提醒 / 漏签扫描；扫码读数由模拟适配器返回，配药端可一键注入碎裂、错放、数量异常。

## 业务规则（全部由代码 + 数据库约束双重保证）

- **医嘱版本失效**：交付新版后旧版 `SUPERSEDED`，旧版药盒立即 `VOID`（保留审计），
  封盒 / 签发 / 交接 / 床旁执行一律阻断；同日可按新版重建药盒。
- **双人复核**：配药人与复核人必须是不同药师（同人签发被拒）；未封盒不得签发；
  禁忌核对不通过不得签发。护理员无权改医嘱（角色强校验）。
- **扫码阻断**：药片碎裂、错放格位、药名 / 规格 / 数量不符 → 格位 `BLOCKED` 并开异常单，
  未闭环不得封盒；复核闭环后可重摆重扫，已停用药品只能撤药。
- **重复给药**：`dose_executions` 上的部分唯一索引保证同一服药格至多一条 `TAKEN`，
  多线程 / 双连接并发确认也只留下一条有效执行。
- **住户外出**：禁止签收；暂缓必须由两人确认（且不能是同一人）。
- **拒服 / 暂缓**：原因必填，自动开异常单；复核填写处理结果闭环，之后可补服签收并自动关单。
- **漏签**：超过餐次窗口（默认 30 分钟）未签收 → `MISSED` + 异常 + 进程内提醒。
- **签发链**：每个状态动作追加 SHA-256 哈希链（`chain` 表），总览页实时显示完整性校验。

## 测试

```bash
python3 -m unittest tests.test_medbox -v
```

24 个用例，覆盖：版本失效与旧盒作废、双签（同人 / 缺签 / 角色 / 禁忌）、
重复执行（含并发双确认）、拒服闭环、外出双人暂缓、碎裂 / 错放 / 规格 / 数量阻断、
漏签、哈希链篡改检出、停药样例数据。

## 目录

```
medbox/
  db.py         SQLite 建表（唯一约束 / 外键 / 签发链表）
  service.py    全部业务规则与状态机
  scanner.py    模拟扫码适配器（可注入故障读数）
  photos.py     本地封盒照片（标准库生成 PNG）
  reminders.py  进程内提醒 / 漏签扫描线程
  seed.py       停药样例演示数据
  server.py     HTTP API + 静态页
  web/          总览 / 配药端 / 床旁端（医疗白 + 青色，红色高风险双提示）
tests/          unittest 测试
```
